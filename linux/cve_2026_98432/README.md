# CVE-2026-98432 — проверка и временная защита

Уязвимость в обработке TCP-хендшейка IPv4 в ядре Linux (use-after-free, CVSS 9.8, есть с ядра 4.4).
Атака идёт по сети, без авторизации. Триггер — SYN с IPv4-опциями (Record Route / Timestamp).
Публичный эксплойт (Anthropic) даёт root на хостах с MPTCP-слушателем.

Правильное решение — ядро с фиксом и перезагрузка. Пока его нет (Ubuntu, RHEL/Alma/Rocky, CentOS 7, старый Debian) — временная защита ниже.

## Быстрый запуск

Проверка:

```bash
bash <(curl -s https://raw.githubusercontent.com/spoveddd/scripts/main/linux/cve-2026-98432/cve98432-check.sh)
```

Поставить защиту (root):

```bash
bash <(curl -s https://raw.githubusercontent.com/spoveddd/scripts/main/linux/cve-2026-98432/cve98432-block.sh)
```

Снять защиту (после перезагрузки на исправленное ядро):

```bash
bash <(curl -s https://raw.githubusercontent.com/spoveddd/scripts/main/linux/cve-2026-98432/cve98432-block.sh) --undo
```

## cve98432-check.sh — проверка

Ничего не меняет на сервере (кроме `apt-get update`). Показывает:

| Строка | Что значит |
|---|---|
| Работающее ядро | есть ли фикс в текущем ядре |
| Установлено с фиксом | ядро с фиксом уже стоит, но сервер не перезагружен |
| В репозитории | доступен ли фикс для установки |
| Правило-блок | стоит ли защита (`nft` / `iptables` / `no`) |
| MPTCP | включён ли MPTCP и сколько MPTCP-слушателей |
| ИТОГ | что делать дальше |

Как определяется фикс:

- **Debian** — версия пакета ядра против исправленных: `6.1.190-1` (bookworm), `6.12.113-1` (trixie, bookworm-backports), `6.18.56-1`, `7.2.13-1` (sid). Для других веток — поиск в changelog.
- **Ubuntu** — поиск `CVE-2026-98432` / названия коммита в changelog ядра; для доступного обновления скачивается changelog кандидата (`apt-get changelog`, может занять до минуты).
- **RHEL / Alma / Rocky / CentOS / Oracle** — `rpm -q --changelog` ядра и `dnf/yum updateinfo list --cve CVE-2026-98432`.
- **OpenVZ / LXC контейнер** — скрипт сразу пишет, что ядро общее с нодой; проверять и чинить на ноде.

Варианты итога:

- `OK — исправлено, правило можно снять`
- `ПЕРЕЗАГРУЗИТЬ — фикс установлен`
- `ОБНОВИТЬ ЯДРО И ПЕРЕЗАГРУЗИТЬ`
- `уязвимо, но ЗАЩИЩЕНО правилом — ждать ядро`
- `УЯЗВИМО — ставить правило`

Если ядро нестандартное (pve, собранное вручную) — пишет «не определить», тогда смотреть вручную.

## cve98432-block.sh — временная защита

Нужен root. Делает:

1. **Дропает IPv4 TCP-пакеты с IP-опциями** до conntrack.
   - если работает `nft` — отдельная таблица `ip cve_2026_98432` (prerouting, priority -300):
     ```
     meta l4proto tcp ip hdrlength gt 5 counter drop
     ```
   - иначе (CentOS 7 и т.п.) — `iptables -t raw -I PREROUTING -p tcp -m u32 --u32 "0>>24&0xF=6:15" -j DROP` с комментарием `CVE-2026-98432`.
2. **Ставит systemd-юнит** `cve-2026-98432.service`, чтобы правило поднималось после перезагрузки и перезапуска nftables.
3. **Выключает MPTCP**: `net.mptcp.enabled=0` + `/etc/sysctl.d/90-cve-2026-98432-mptcp.conf`. Уже открытые MPTCP-слушатели остаются — скрипт их покажет, эти сервисы надо перезапустить.
4. Предупреждает, если `net.ipv4.tcp_migrate_req=1` (второй путь атаки).

Создаваемые файлы:

```
/etc/systemd/system/cve-2026-98432.service
/etc/cve-2026-98432.nft            # только в режиме nft
/etc/sysctl.d/90-cve-2026-98432-mptcp.conf
```

`--undo` удаляет правило, юнит, эти файлы и возвращает `net.mptcp.enabled=1`.

### Побочные эффекты

- Обычный трафик IP-опций не несёт (RFC 7126 рекомендует такие пакеты дропать), на сайты и SSH не влияет.
- IPv6, UDP, ICMP не затрагиваются.
- Не ставить на сетях с CIPSO / NetLabel (SELinux labeled networking) — там IP-опции нормальны.
- Если сервер маршрутизирует трафик для других машин, транзитные TCP-пакеты с IP-опциями тоже будут отброшены.
- Правило уменьшает риск, но не заменяет обновление ядра.

## Порядок работы

1. Запустить проверку.
2. `ОБНОВИТЬ ЯДРО` → `apt full-upgrade` / `dnf update kernel*`, перезагрузка, проверка ещё раз.
3. `УЯЗВИМО` → поставить защиту, проверка должна показать `ЗАЩИЩЕНО`.
4. Когда выйдет ядро — обновить, перезагрузить, проверка покажет `OK`, снять защиту через `--undo`.
