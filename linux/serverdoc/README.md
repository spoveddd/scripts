# serverdoc

Диагностический инструмент для серверов виртуального хостинга с панелями
управления. Определяет состояние стека (Apache/nginx/PHP-FPM/MySQL),
анализирует исчерпание ресурсов и предлагает решения — оставляя финальное
решение за инженером.

Панели: ISPmanager · FastPanel · HestiaCP

## Установка и запуск

Одной командой — скачать готовый статический бинарь и запустить:

```
curl -fsSL https://raw.githubusercontent.com/spoveddd/scripts/main/linux/serverdoc/dist/serverdoc-linux-amd64 -o /usr/local/bin/serverdoc \
  && chmod +x /usr/local/bin/serverdoc \
  && serverdoc
```

В дальнейшем достаточно `serverdoc`. Для ARM-серверов — замените `amd64` на `arm64`
в URL.

## Использование

```
serverdoc                # человекочитаемый отчёт
serverdoc --json         # машинный формат (JSON)
serverdoc --no-color     # без ANSI-цветов
serverdoc --version      # версия и выход
```

Запускать **от root** — для доступа к CLI панелей и `/proc/<pid>/exe`.

## Статус

**Фаза 1 — инвентаризация (готова).** Определение панели, состава стека
(включая Apache MPM), версий PHP-FPM с подсчётом пулов, список сайтов
через CLI панели с разбивкой по handler и PHP-версии.

Дальше:
- **Фаза 2** — анализ состояния (зависшие воркеры, классификация MySQL,
  топ-сайты по нагрузке из access-логов).
- **Фаза 3** — арифметика памяти.
- **Фаза 4** — рекомендации (версионируемая YAML-база правил).
- **Фаза 5** — bash-инсталлятор и официальные релизы.

## Сборка из исходников

Нужен Go 1.21+. Бинарь статический (`CGO_ENABLED=0`) — на сервер
попадает только бинарник, Go там не нужен.

```
make build          # под текущую систему
make build-all      # статичные linux/amd64 и linux/arm64 в dist/
make vet            # go vet
make run            # собрать и запустить
```

## Структура

```
cmd/serverdoc      точка входа
internal/sys       системная информация, хелпер запуска команд с таймаутом
internal/panel     определение панели, список сайтов (mogwai/mgrctl/v-list-*)
internal/stack     инвентаризация Apache(MPM)/nginx/MySQL/PHP-FPM
internal/report    рендер отчёта (текст/JSON)
```

## Принципы

- **Только read-only.** Никаких авто-изменений на сервере. Финальное решение —
  за инженером.
- **Без внешних зависимостей.** Только стандартная библиотека Go.
- **От реального вывода, а не от документации.** Парсеры выверены по
  живым выводам `mogwai --json sites list`, `mgrctl -o json webdomain`,
  `v-list-web-domains <user> json`.
- **Каждая рекомендация (в будущих фазах) — с цепочкой "что увидел →
  что из этого следует → уверенность".** Без угадывания одной причины.
